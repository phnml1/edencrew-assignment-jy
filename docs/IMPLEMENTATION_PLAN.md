# 과제 1 구현 계획

## 현재 프로젝트 상태

- Flutter 스타터 템플릿 상태이다.
- `lib/main.dart`에는 토큰 사용 예시용 `StartHereScreen`만 있다.
- 디자인 토큰은 `lib/theme`에 준비되어 있고 `AppTheme.dark`가 연결되어 있다.
- 화면 코드는 `context.colors.*`, `context.dimens.*`, `AppTypography.*`를 사용한다.
- 화면 코드에서 색상 hex 값이나 `AppPalette`를 직접 사용하지 않는다.

## 구현 우선순위

1. 앱 구조와 공통 모델을 만든다.
2. Naver API 응답을 앱 모델로 변환하는 계층을 만든다.
3. 관심 상태를 세 화면에서 공유하도록 상태 관리를 만든다.
4. 관심 화면을 먼저 구현한다.
5. 검색 화면을 구현하고 관심 상태와 연결한다.
6. 종목 상세 화면을 구현한다.
7. 예외 상태와 README 메모 항목을 정리한다.

- `StockQuote`

  - 등락액
  - 등락률

  - 거래량
  - 시가총액

  - 날짜

  - 실시간 시세
  - 일별 시세 목록

## Naver API 구현 단위

- 검색 자동완성
  - 국내 주식만 사용한다.
  - 6자리 종목코드만 통과시킨다.
  - canonical id를 `domestic:{symbol}` 형태로 만든다.
- 실시간 시세
  - 관심종목 여러 개를 한 번의 요청으로 조회한다.
  - symbol 기준 map으로 정리한다.
  - 등락액은 `nv - pcv`로 계산한다.
  - 등락률은 `(nv - pcv) / pcv`로 계산한다.
  - 시가총액은 `nv * countOfListedStock`으로 계산한다.
- 종목 메타데이터
  - 종목명과 거래소명을 UI 모델에 연결한다.
- 일별 시세 HTML
  - HTML 인코딩을 고려해 파싱한다.
  - 날짜는 내부에서 `yyyyMMdd`로 정규화한다.
  - 기간 탭에 필요한 페이지까지만 요청한다.
  - 이미 받은 페이지는 재사용한다.
  - `lastPage`보다 큰 페이지를 요청하지 않는다.

## 상태 관리 초안

- Flutter 처음 진입 기준으로 과한 구조는 피하고 `ChangeNotifier` 기반 상태로 시작한다.
- 관심 상태는 하나의 공유 store에서 관리한다.
- store가 담당할 항목:
  - 관심종목 목록
  - 관심 등록 / 해제
  - 현재 관심 여부
  - 관심 화면 정렬 기준
  - 관심종목 시세 새로고침
  - 검색 / 상세 화면에서 변경된 관심 상태 동기화

- 정렬 바텀시트 표시
